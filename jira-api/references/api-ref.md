# Jira Cloud REST API v3 Reference

Base URL: `https://<site>.atlassian.net/rest/api/3`
Auth: `Authorization: Basic base64(email:api_token)`

## Endpoints used by this skill

| Operation        | Method & Path                                    |
|------------------|--------------------------------------------------|
| Verify login     | `GET /myself`                                    |
| List projects    | `GET /project/search?maxResults=100&orderBy=name`|
| Create issue     | `POST /issue`                                     |
| Get issue        | `GET /issue/{key}?fields=...`                     |
| Search (JQL)     | `POST /search/jql`                               |
| Add comment      | `POST /issue/{key}/comment`                      |
| List transitions | `GET /issue/{key}/transitions`                   |
| Apply transition | `POST /issue/{key}/transitions`                  |
| Issue types      | `GET /issue/createmeta/{key}/issuetypes`         |

> Note: the legacy `GET /search` endpoint is deprecated on Jira Cloud in favor of
> `POST /search/jql` (the "enhanced JQL" search). This skill uses the new one.

## Create issue payload

```json
{
  "fields": {
    "project":   { "key": "PROJ" },
    "issuetype": { "name": "Story" },
    "summary":   "Short summary line",
    "description": { "type": "doc", "version": 1, "content": [ ... ] },
    "labels":    ["protostar", "cli"],
    "parent":    { "key": "PROJ-1" },
    "priority":  { "name": "High" }
  }
}
```

- `project.key` and `issuetype.name` are required. `summary` is required.
- `parent` is required when `issuetype` is `Sub-task`, and is how you attach a
  story to an Epic on team-managed projects.
- `priority` and other fields must be present on the project's **create screen**,
  or the API returns a `400` naming the field. Omit fields that error.

## Atlassian Document Format (ADF)

Jira Cloud v3 does not accept plain strings for `description` or comment `body` —
they must be ADF documents. The minimal shape is:

```json
{
  "type": "doc",
  "version": 1,
  "content": [
    { "type": "paragraph", "content": [ { "type": "text", "text": "Hello" } ] }
  ]
}
```

The script's `TextToAdf` splits input on blank lines into one paragraph per block.
Richer formatting (headings, bullet lists, links) is possible but not generated by
this skill; pass prose paragraphs.

## JQL examples

| Goal                                  | JQL                                              |
|---------------------------------------|--------------------------------------------------|
| Open issues in a project              | `project = PROJ AND statusCategory != Done`      |
| Everything labeled protostar          | `labels = protostar ORDER BY created DESC`       |
| Stories assigned to me                | `assignee = currentUser() AND issuetype = Story` |
| Recently updated                      | `updated >= -7d ORDER BY updated DESC`           |

## Common error codes

- `400` — bad field (often issuetype name or a field not on the create screen).
  Run `issue types --project <KEY>` to confirm valid type names.
- `401` — wrong email/token pair.
- `403` — authenticated but lacking permission for the resource.
- `404` — issue/project key does not exist or is not visible to the account.
